# Estimation Workflow

[← Documentation home](./README)

This is a simple flow that matches the workspace layout. It is designed to keep estimates consistent and easy to review.

---

## 1. Create or select a project

Use New Estimation to start fresh or select an existing project from the sidebar.

Checklist:
- Add a clear project name (client or product plus scope).
- Capture key assumptions in task descriptions (what is included and excluded).

## 2. Add categories

Create high level buckets such as Discovery, Design, and Build. Keep categories short and clear.

Suggested starting categories:
- Discovery and planning
- Design
- Implementation
- QA and release
- Project management

## 3. Add tasks

For each category, add tasks and assign roles with hours. You can split hours across multiple roles.

Tips for task writing:
- Prefer concrete deliverables (“Build onboarding flow”) over vague activities (“Work on UI”).
- Add acceptance criteria to the task description when it reduces ambiguity.
- If a task is risky, use risk markup instead of guessing large hour buffers.

## 4. Assign roles and rates

Set rates per role in the Pricing and Team panel. Rates are used for totals and summaries.

Notes:
- Use one role per responsibility, not per person.
- Keep rates consistent across projects by setting defaults in your profile preferences.

## 5. Configure sprints

Set sprint length, number of sprints, and meetings. This creates a capacity view and meeting load totals.

Use sprint planning to answer:
- Does the total effort fit the planned delivery window?
- Do meetings add meaningful overhead for your team size?

## 6. Review totals

Check the Summary panel for effort, risk buffer, and final totals.

Before you share an export, double check:
- total hours by role
- any risk markup or general costs you applied
- sprint capacity and remaining capacity

## 7. Save and export

Click Save to persist. Use Export to generate Excel or PDF summaries.
