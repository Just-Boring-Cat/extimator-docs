# Sprint Planning and Meetings

[← Documentation home](./README)

Sprint settings let you compare estimated effort with delivery capacity. This is especially useful when you need to justify a timeline, not just a total.

---

## Sprint length and count

Set the length in weeks and number of sprints. This is used to estimate total available capacity.

Practical guidance:
- For most teams, 1 or 2 week sprints are easiest to reason about.
- If you are estimating for a client timeline, set the sprint count to match the target delivery window, then confirm whether capacity is realistic.

## Meetings

Create meeting templates with:
- Name
- Frequency per sprint
- Duration
- Roles that attend

Meetings only count toward effort if at least one role is selected.

Common meeting templates:
- Sprint planning
- Daily standup
- Review and demo
- Retrospective
- Client status call

## Capacity and load

The sprint panel shows:
- Planned capacity
- Estimated load
- Remaining capacity

Use this to validate whether the estimate fits the available delivery window.

What to do when capacity is negative:
- reduce scope (remove tasks or lower effort assumptions)
- increase time (more sprints)
- increase capacity (more people, more hours per week, fewer meetings)
